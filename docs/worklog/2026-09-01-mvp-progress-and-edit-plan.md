# MVP 进度盘点与编辑功能计划

- 日期：2026-09-01
- 状态：已完成

## 背景

项目已经完成日历创建、待办管理和今日总览的第一版闭环。本次补齐日程和待办编辑能力，使用户不必通过删除后重新创建来修正安排。

## 当前进度

- 日历：支持创建、查询、编辑、删除、时区校验和基础冲突检测。
- 待办：支持创建、查询、编辑、完成/恢复、删除、优先级和截止时间。
- 今日总览：支持系统时间、今日事件、今日到期待办和课程兜底展示。
- 存储：当前使用本地 JSON 原子写入，符合单用户本地 MVP 需要；PostgreSQL 和 Rust/Axum 迁移暂不提前引入。

## 第一阶段目标

实现日程和待办编辑，并保持现有数据校验边界：

1. 日程编辑可以修改标题、开始时间、结束时间、地点和备注。
2. 编辑日程时排除自身后重新检查时间冲突。
3. 待办编辑可以修改标题、优先级、截止时间和备注。
4. 完成状态只能通过现有完成/恢复接口改变，避免编辑时意外重置状态。
5. 首页编辑操作打开已有数据，保存成功后刷新对应列表和今日总览。

## 决策

- 延续现有 REST 风格接口：日程使用 `PUT /api/calendar?id=...`，待办使用 `PUT /api/todos?id=...`。
- 编辑接口继续由后端模型、服务层统一校验，前端不直接操作文件。
- 所有日期时间继续要求带时区的 ISO 8601 格式。
- 继续使用当前 JSON 存储，待核心行为稳定后再按技术路线迁移到 Rust domain 和 PostgreSQL。

## 验收与验证

- 创建一条日程或待办后可以打开编辑表单并回填原内容。
- 修改后刷新页面，列表显示新内容。
- 日程修改造成冲突时保存失败，原事件保持不变。
- 无效时间、空标题和非法优先级返回可读 JSON 错误。
- 新增测试覆盖服务层编辑、冲突回滚和 API 输入校验；完整测试套件保持通过。

## 验证结果

新增服务层编辑、冲突保护和完成状态保留测试；前端脚本语法检查及完整测试套件已通过。

## 后续事项

编辑功能完成后，再扩展更复杂的重复规则和真实通知调度。目前已支持每天、每周、工作日重复和提醒计算接口，外部通知渠道仍待接入。
