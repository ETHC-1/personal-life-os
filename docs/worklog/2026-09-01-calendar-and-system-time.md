# 日历与系统时间后端

- 日期：2026-09-01
- 状态：已完成

## 背景

项目已有课程课表存储，但还没有用于个人安排的独立日历事件模型，也没有统一读取服务端当前时间的接口。

## 决策

- 日历事件与课程模块分离，使用独立的 `CalendarStore` JSON 文件保存，并接入现有 Web 首页。
- 所有事件时间必须带时区；创建事件时拒绝重叠安排。
- 系统时间默认以 `Asia/Shanghai` 返回，同时提供 UTC 时间，均使用 ISO 8601。
- Web 层只负责请求校验和调用服务，数据写入仍由后端模型与存储层完成。

## 接口

- `GET /api/time?timezone=Asia/Shanghai`
- `GET /api/calendar?start=...&end=...`
- `POST /api/calendar`，请求体包含 `title`、`starts_at`、`ends_at`
- `DELETE /api/calendar?id=...`

## 验证结果

新增日历模型、冲突检测、时区处理、Web 查询和首页创建流程；完整测试套件已通过。

## 后续事项

可在此基础上增加日程编辑、待办编辑、重复规则、提醒和课程事件的统一日历视图。
